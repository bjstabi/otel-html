# Development loop and CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut the CI run from ~9 to ~4 minutes and a one-spec local e2e run from 34 s to ~3 s, and make `mise run check` skip what nothing changed, in five pull requests that each leave CI green.

**Architecture:** The CI jobs stop waiting on each other and each builds `dist/` itself (3 s). The e2e fixture reports move out of Playwright's global setup into a mise task with `sources`/`outputs`, so mise decides when they are rebuilt; the `http` Playwright project runs only tagged specs and the `@perf` tests get their own project, so the two passes halve. Every mise task then declares its inputs and the check tasks cache their results; the e2e task caches its result too, keyed on everything a browser run reads, and every CI job restores the mise task cache, so "what needs to run" is decided by mise on CI exactly as it is locally, with no GitHub-side path rules and no script of our own. Coverage comes last, as an artifact and a job summary on `main`, always from the full suite.

**Tech Stack:** mise 2026.10.25 (task freshness, experimental artifact cache, `[task_config.input_groups]`), Playwright 1.64.1 (project `grep`/`grepInvert`, `{ tag }`), vitest 5.0.5 (`--changed`, `@vitest/coverage-v8` 5.0.5), bun for scripts, GitHub Actions (`actions/cache`).

**Spec:** `docs/superpowers/specs/2026-11-01-dev-loop-assessment.md` (proposals P1–P16; decisions marked **decided**). The measured baseline is in its first section; each PR body records the after figure next to it.

## Pull requests

The repository squash-merges: **the PR title is the conventional commit** that lands on `main`; the body carries the measurements and an "Also" list for anything fixed on the way. **Execution (decided 2026-11-01):** subagent-driven, under the unattended process (`docs/agents/process-unattended.md`); the follow-up candidates in the spec are re-evaluated once all five PRs have merged, not ticketed now (#96, Codecov, already exists).

## Global Constraints

- The constraints of the earlier plans hold: no `any`, no non-null assertions, Biome strict at error, TDD per task (failing test, run it, implement, run it, commit), `pnpm exec biome check .` and `mise run typecheck` by hand before each commit, commit messages end with the session's trailers.
- **No new runtime dependency.** The only new dev dependency is `@vitest/coverage-v8@5.0.5` (PR E). Scripts run under `bun` like `scripts/*.ts`; their pure parts live in exported functions tested from `test/scripts/`.
- **CI YAML:** actions stay pinned by SHA as they are; `actionlint` (in `mise run lint`) passes; every job that uses the `otel-html run` job shell builds `dist/` in a `shell: bash` step before its first `run:` step (ci.yml's existing comment); `MISE_DISABLE_TOOLS: claude` stays.
- **mise:** task names and `-- args` that CI uses today keep working: `mise run check`, `mise run build`, `mise run test:e2e -- <playwright args>`, `mise run test:e2e:chromium -- <playwright args>`. Settings go in `[settings]` of `mise.toml` (the config is trusted locally and on CI). Never cached: `test:unit:perf`, `test:load*`, `coverage`; `test:e2e` is cached only with the inputs Task 8 lists.
- **Tasks document themselves:** every task has a `description` (multi-line where the README used to explain it); the README's task table is generated between `<!-- mise-tasks -->` markers by `mise generate task-docs --inject --output README.md`, run by `gen` and checked by `gen:check`. No hand-written task table anywhere.
- **Measurements in PR bodies:** each PR body states the CI critical path (`gh run view <id> --json jobs`) and, for B and C, the local timings of `mise run test:e2e:chromium -- e2e/smoke.spec.ts` (first and second run) and `mise run check` (first and second run), next to the spec's baseline.
- Test commands: a single vitest file is `pnpm exec vitest run <file>`; a single spec is `mise run test:e2e:chromium -- e2e/<spec>.spec.ts`; `pnpm exec playwright test --list ...` lists without running.

## Review Focus

1. **A fresh clone, `mise run test:e2e:chromium -- e2e/smoke.spec.ts`.** Expected: the fixtures build once, the spec passes, the second invocation prints `[e2e:fixtures] sources up-to-date, skipping` and finishes in under 10 s. Pinned in Task 3.
2. **`e2e/.reports` exists, then a viewer source file changes.** Expected: `mise run build:viewer` runs, then the fixtures rebuild (stale reports that still pass are the worst failure this plan can introduce). Pinned in Task 3.
3. **A tagged `@http` test that fails only over http.** Expected: `chromium-http` still runs it and the run goes red. Pinned in Task 4 (`--list` output).
4. **A docs-only push.** Expected: every job still starts; `check`'s cached tasks and `test:e2e` replay from the cache (`cache hit` in the log, the replayed Playwright summary), the run takes ≈ 1.5 min, the PR's checks are all satisfied. Pinned in Task 9.
5. **A test edited to fail after a cached pass.** Expected: `mise run check` runs it (a source changed) and fails; a cached result is only ever a *successful* one, keyed on the sources. Pinned in Task 6.
6. **The Playwright image tag in `ci.yml` is bumped and nothing else changes.** Expected: `test:e2e` runs again, not a replay (the workflow file is one of its sources). Pinned in Task 9.

# PR D — the same semantics on CI (P6)
