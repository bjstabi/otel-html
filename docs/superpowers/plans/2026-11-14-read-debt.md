# Read debt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drop format 4, then pay the last five `KNOWN_DEBT` lines: metric run queries and the summary's quantiles stop reading points files
the answer does not need (#295), and a trace is read from the row groups that hold it (#291, format 6).

**Architecture:** PR 0 removes format 4: `main` reads only the current format and the one before it, so the
deployer skips the format-4 runs still retained and the rolling report loses them at the next deploy. PR 1 changes only the viewer's metric reads: the summary's quantiles join the memoised catalogue
load, and `metricRunQuery` selects its runs from the files at or after the window's start, then reads those runs'
files by their `runBy` statistic. PRs 2–4 add format 6 readers first, then writers, then the viewer's use of it:
`traces.parquet` gains `span_rows`, the `file_row_number` ranges of a trace's spans per row group, and a trace is read
with one `BETWEEN` per range joined by `UNION ALL`.

**Tech Stack:** TypeScript, DuckDB-WASM 1.32.0 (DuckDB 1.4.3), Parquet via the repo's codec, vitest, Playwright, mise.

**Spec:** `docs/superpowers/specs/2026-11-14-read-debt-design.md` (approved 2026-11-14).

**PR process:** unattended (`docs/agents/process-unattended.md`). One PR per row, in order; each starts from `main`
after the previous one merged. Implementers and task reviewers on Sonnet 5.5; the branch review on Opus 5.5. The
maintainer lifted the stop for the files these tasks list under `src/format/`, `src/writer/`, `src/cli/` and
`src/host/`; any other file the deployer runs, and every workflow and action file, is still a stop.

## Global Constraints

- No answer changes: the same runs, cells, `n_series`, `left_out`, quantile list, trace spans and service shares as on `main`.
- No catalogue entry gets worse on any axis (`test/scaling/classes.test.ts`); a debt line is set `measured: true`, the class test run, then the line deleted.
- Readers before writers: nothing writes format 6 until PR 2 (which reads it) is on `main`.
- Compatibility is kept for the previous format only (maintainer, 2026-11-14: no external users). It is needed because jobs push run updates through the released actions while the deployer runs `main`. After PR 0, `main` reads format 5; after PR 2, formats 5 and 6. Formats 1–3 stay convertible by `merge` (unchanged). A traces file without `spanRows: true` is read as today.
- `span_rows` is `list_int64`, nullable, the last column of `traces`: pairs `[first0, last0, first1, last1, …]` of `file_row_number` in that partition's spans file, at most one pair per spans row group, pairs ascending.
- A format-6 manifest has format 5's shape plus `spanRows: true` (optional) on a `traces` file entry; the entry has it exactly when the file has the `span_rows` column.
- A trace's ranged read is `UNION ALL` of one statement per range (`trace_id = … AND file_row_number BETWEEN first AND last`); never an `OR` of ranges (it does not prune, spec §2).
- No workflow or action file changes. `mise run check` after every task; `mise run verify` before each PR.
- Commits and PR titles per `docs/agents/conventions.md`; PR bodies carry the catalogue counts and the class moves.

## Review Focus

1. A trace split across partitions where some traces files have `spanRows` and others do not: every span comes back once (Task 10 test).
2. A malformed trace (a span ending before it starts) under ranges: the "fewer rows than `span_count`" re-read still happens (Task 10 test).
3. A run that starts before the window and has its latest point inside it keeps its earlier points in its cells; a run whose latest point is after the window stays out (Task 2 equivalence test).
4. `runBy` that is not a statistics key, or a points file whose statistic is `null`: every earlier file is still read and the answer is the same (Task 2 test).
5. The CI publishing path: a released 0.3.x component never has to read a report or update that the `main` build wrote in format 6 (Task 6 step, listed in PR 2's body; a place where it does is a stop).
