# Format 6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Format 6 stores each trace's exclusive time per service in `traces.parquet` and drops the manifest epoch, so
the trace list draws "Latency by service" without reading spans and reports of any width can be written and read;
then a batch PR fixes #241, #193, #212 and `run`'s exit code.

**Architecture:** One shared share module computes the share for both the writer (flush, compaction) and the viewer's
fallback. Readers (PR A) land first and accept format 6 written by a test helper; writers (PR B) follow after a check of
the CI publishing path. The viewer anchors relative times on the epoch (format 5) or the range start frozen at page
load (format 6); format-6 URLs carry absolute times.

**Tech Stack:** TypeScript, DuckDB-WASM views, the repository's Parquet codec, vitest, Playwright, mise tasks.

**Spec:** `docs/superpowers/specs/2026-11-14-format-6-design.md`

## Global Constraints

- Process: unattended (`docs/agents/process-unattended.md`); PRs target `main`; squash-merge when CI is green and
  CodeRabbit's valid comments are fixed. Implementers and task reviewers on Sonnet 5.5, branch reviews on Opus 5.5.
- Readers read formats 5 and 6; no format-4 support returns. PR B merges only after PR A and after Task 3 step 4's
  audit says no released 0.4.x component reads what `main` writes in format 6 (else: stop, a release is needed).
- `service_share`: VARCHAR JSON, `[[service, "ns"], …]`, largest first, ties by service name; `[]` for a trace with no
  spans in the partition; null only where unknown.
- A trace's stored share is exact when it has spans in exactly one traces row and that share is not null; otherwise
  the cell falls back to `serviceShare` with `SERVICE_SHARE_SPAN_CAP` (10,000) unchanged.
- Format 6 has no `epochUnixNano` in the manifest. The viewer's anchor: format 5 → `epochUnixNano`; format 6 →
  `range.start`, or `createdAt` in unix ns for an empty report; frozen for the page's life.
- Format-6 URLs carry absolute unix-ns times; format-5 URLs are unchanged.
- Beyond 2^53 ns from the anchor the viewer rounds to the nearest double instead of refusing; durations stay exact.
- Writer sessions anchor on their own first record; a session whose own data spans more than 2^53 ns refuses with a
  message naming that span. `merge`'s conversion of chunk inputs keeps its window.
- Write cost: the share may add up to 10 % wall time; a peak-RSS rise above 25 % on the `branch/main` merge is a stop.
- Commits: conventional, header ≤ 100 chars, subject not sentence-case, body lines ≤ 100, trailers
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and the session's `Claude-Session:` line.
- `mise run check` before every commit; `mise run verify` before opening a PR.

## Review Focus

1. A CI trace holding both the provisional and the final copy of a span: the stored share equals the viewer's fallback
   (one copy counted). Pinned in Task 2.
2. A Refresh that finds data older than the report's range on a format-6 report: the anchor, the URL's `t` and the
   window on screen do not move. Pinned in Task 4.
3. A format-6 URL whose window starts before the range start (a shared link after older data arrived): it opens and
   shows that window, no refusal. Pinned in Task 4.
4. A report mixing a format-5 copy and format-6 partitions where one trace spans both: its cell falls back, the others
   draw from the stored share. Pinned in Task 5.
5. A compaction whose inputs split one trace between a format-5 copy and a format-6 flush: the output share is
   recomputed from the merged spans, not null and not one input's share. Pinned in Task 7.
