# otel-html M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship milestone M1 of otel-html: a strict TypeScript repo that converts OTLP files (or OTel SDK spans) into a static, `file://`-safe report folder with a working Traces explorer and trace panel, plus CI, release automation and standalone binaries.

**Architecture:** One npm package. Node-side modules (`api`, `cli`, `writer`) feed every input through one **writer session** (open → add → flush/checkpoint → close) that writes columnar `__OH__.push(...)` data scripts, mergeable-by-reingest rollups, a trace index and an atomically replaced manifest. Browser-safe shared modules (`model` types, `format`, `ottl`, `rollups`, `semconv`) are imported by both the writer and the React viewer, which Vite bundles as a classic IIFE copied into every report. Every entry point has one composition root; collaborators are injected as small interfaces.

**Tech Stack:** Node 24 LTS, pnpm 12, TypeScript 7.0, Biome 2.6, knip 6, lefthook, commitlint 21, Vitest 5, Playwright 1.64, protobuf-es 2.16 (+ buf 1.75, opentelemetry-proto v1.11.1), Zod 4.6, Lezer (generator 1.8 / lr 1.4), commander 15, yaml 2.9, `@opentelemetry/api` 1.10 + `sdk-trace-base` 2.12, React 19.3, Vite 8.3, tsdown 0.23, ECharts 6.1, Tailwind 4.3, Zustand 5, wouter 3, TanStack Virtual 3 / Table 9, Base UI 1.9, Lucide, react-json-view-lite 2.5, Bun 1.4 (`build --compile`), release-please v5.

**Spec:** `docs/superpowers/specs/2026-10-25-otel-html-design.md` (approved). Mockups: `docs/superpowers/specs/2026-10-25-otel-html-mockups/01-trace-explorer.html`, `02-trace-drilldown.html`.

**Scope boundaries (M1 only):** Logs and metrics are **ingested, stored, counted and merged** (so no data is ever dropped and the format is stable), but their explorers, log patterns, metric multi-resolution series and log↔trace tabs are M2/M3. SDK→OTLP mapping covers spans only; SDK logs/metrics mapping ships with the exporters in M5. The receiver, `serve`, `run`, `load.yml`, dashboards/Fusion and the `dashboards`/`views` config sections are M4/M5. Because `run` is M5, CI dogfooding (spec §11.2) starts in M5.

**Plan-level calls (flag at review if wrong):**
- `merge` and append reuse the writer session by **re-ingesting decoded chunk records**, so rollups need only `add` + `serialize`/`deserialize`, not pairwise merge functions. This keeps one code path (§7.5) and makes merged rollups exact.
- All in-memory and on-disk timestamps are `RelNanos`: a JS number of nanoseconds relative to the report's `epochUnixNano` (stored once in the manifest as a decimal string). That keeps sorting and arithmetic fast in the viewer. Offsets beyond ±2^53 ns (about 104 days) fail fast.
- Logs and metric points use the same declarative column codec as spans, with point-kind-specific fields in a `json` column, so M2/M3 can refine the encoding without changing the session.

## Global Constraints

- TypeScript only; ESM source; strict flags: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`, `isolatedDeclarations` (public API).
- No `any`, no non-null assertions, `unknown` at boundaries, exhaustive `switch` via `never`; Biome recommended + strict rules all at **error**; formatter diff fails.
- Fail fast at every boundary (OTLP input, config, CLI args, URL state, report data files) with a precise message: path, field, expected vs actual. No silent fallbacks.
- DI via plain factories/interfaces; one composition root per entry point; no module-level singletons; no DI container, decorators or `reflect-metadata`.
- One Zod config schema; precedence defaults < config file < env vars < CLI flags / API args; OTel names where OTel already defines a setting.
- Domain rules are data tables (semconv groups/formatters, default facets, span tabs, severity mapping, column specs).
- Report: `index.html`, `.nojekyll`, `assets/viewer.<hash>.js`, `data/manifest.js`, `data/rollups/*.js`, `data/chunks/<signal>/<n>.js`, `data/traces/<shard>.js`, `data/state/`. No path starts with `_`. Relative paths only.
- `file://` rules: no `fetch`/XHR, no ES-module scripts, no separate worker files, no network WASM; hash routing; `localStorage` optional and wrapped in try/catch.
- Browser-safe shared dirs (`src/model`, `src/format`, `src/ottl`, `src/rollups`, `src/semconv`, `src/viewer`) must not import `node:*` (enforced by Biome `noNodejsModules` override).
- Design tokens: page `#f6f6f3`, surface `#ffffff`, ink `#16181d`, accent teal `#0f766e`, selected state = solid ink pill, cards radius 10–12px, system UI font, monospace tabular numerals for times/durations/IDs/attribute keys+values. Categorical: `#2a78d6, #eb6834, #1baf7a, #eda100, #e87ba4, #008300, #6250d6` in fixed order; status critical `#d03b3b`, warning `#fab219`; color never alone for errors.
- No vendor colors, logos, icons, CSS, copy or trademarks; no node-graph service map. README states it is not an official OpenTelemetry project.
- Span tabs shown only when OTel data can fill them; never Database, Infrastructure, Processes, Network or Profiles.
- `mise run check` (lint, format check, typecheck, unit tests) under 60 s on a laptop.
- Conventional commits; every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Targets (e2e perf check, ubuntu-latest): 100k-span report opens to interactive Trace Explorer < 3 s; filter/facet toggle < 150 ms; writer peak RSS < 512 MB; ≤ ~300 bytes/span on disk.

## Review Focus

1. **Hostile strings in telemetry** (`</script>`, `<img onerror=…>`, U+2028/U+2029 in span names, attribute values, status messages): the report must not break or execute anything; values render as text. Pinned in Task 9 (data-file escaping) and Task 22 (rendering).
2. **int64 nanosecond timestamps written as JSON numbers** above 2^53 (OTLP JSON allows numbers or strings): no precision loss; nanosecond-exact durations. Pinned in Task 4.
3. **Incomplete traces** (parent span never arrives; spans of one trace spread across files/chunks; child starts before parent): orphans render as additional roots, nothing is dropped, and the trace still opens. Pinned in Task 11 (trace index), Task 16 (tree building) and Task 21 (flame layout).
4. **Writer killed mid-flush**: the folder still opens and shows everything up to the last completed flush; a later append continues cleanly; a stale lock from a dead PID is reclaimed with a warning. Pinned in Task 11 (crash and lock tests) and Task 12 (append).
5. **Empty and traces-less inputs** (an empty `resourceSpans`, a logs-only file, zero files matched): convert succeeds with a valid report that opens to designed empty states; zero input files is a usage error. Pinned in Task 11 (logs-only session), Task 12 (convert) and Task 23 (empty-state e2e).
