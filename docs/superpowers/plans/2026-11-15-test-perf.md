# Faster Tests and Checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The same tests and checks, faster: fixtures built once, a pooled DuckDB, balanced shards, fewer and shorter CI jobs, and a pre-push hook that runs only what a change can break.

**Architecture:** Four ordered phases on one branch (quick wins → fixtures once → DuckDB pool → CI structure), each ending
with a measurement and `mise run verify`. Caching goes through mise tasks with declared outputs; CI caches the same
folders only where the local cache cannot reach. Pooled or shared resources must hand each test the state a fresh one
would.

**Tech Stack:** mise tasks (`mise.toml`), vitest 4 (forks pool, `WeightedShardSequencer`), DuckDB-WASM Node build,
Playwright, lefthook, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-15-test-perf-design.md` (approved 2026-11-15). Evidence:
`.superpowers/sdd/2026-11-15-test-perf/{unit-node,scaling-viewer,e2e,checks-pipeline}.md` (git-ignored working notes).

**Process:** unattended (`docs/agents/process-unattended.md`). One branch, one PR:

| branch | PR title (the squash commit) |
| --- | --- |
| `perf/tests` (cut from `main`) | `perf(test): build fixtures once, pool DuckDB, rebalance shards and trim CI` |

Phases (in order, all on `perf/tests`; each ends with its measuring task and `timeout 1200 mise run verify`):

1. **Quick wins** — Tasks 1–8
2. **Build fixtures once** — Tasks 9–14
3. **A DuckDB instance pool** — Tasks 15–16
4. **CI structure** — Tasks 17–20 (Task 20 also collects every number for the PR body and opens/merges the PR)

## Global Constraints

- No assertion is dropped to save time; the only exception is the fixed 6 s wait in `test/cli/host.test.ts` (it only waited).
- A pooled or shared resource gives each test the state a fresh one would. A pool that can return stale results is a failure even if faster.
- Caching belongs in local tools first (mise task cache, declared `outputs`); CI caches the same outputs only where a local cache cannot reach.
- Merged scaling shapes stay. No page reuse across e2e tests (#286 deferred).
- `verify` before a PR stays the rule. Every long command runs in the foreground with a timeout (`timeout 1200 mise run verify`), never a `pgrep -f`/`pkill -f` loop; nothing is left running at hand-back.
- Every timing run is wrapped in `flock /tmp/claude-1000/-home-coder-workspace-otel-html/60dbcef7-aea8-4948-b0a3-4f384b9358b2/scratchpad/measure.lock` (written `$LOCK` below) and prefixed with `/usr/bin/time -f '%e s'`; numbers go into `.superpowers/sdd/2026-11-15-test-perf/measurements.md` (git-ignored), one line per measurement: `phase | what | before | after | command`.
- A new or changed mise task updates its `description` and runs `mise run gen` in the same commit (README's Development section is generated; `gen:check` enforces it).
- Every new test file gets an entry in `test-support/shard-weights.json` in the commit that adds it (Task 3's test enforces it): the seconds `pnpm exec vitest run <file>` reports, rounded to a tenth; Task 20 refreshes the whole table.
- Conventions: `docs/agents/conventions.md` (TS strict, no `any`, typed `OtelHtmlError`s, conventional commits with the session trailers, `pnpm exec biome check .` and `mise run typecheck` before each commit). No new dependency.
- Touching `.github/actions/otel-html-collect`, `.github/actions/setup` and `.github/workflows/ci.yml` is approved by the spec. `release.yml`, `ci-report.yml`, `pages-deploy.yml`, `otel-html-publish` and `otel-html-deploy` are not touched; a change there is a stop-and-ask.
- Until Task 2 lands, a fresh worktree needs `mise run build` before `mise run check`.

## Review Focus

1. **A warm scaling cache must not replay measurements.** `test-support/scaling/measure.ts` shares `measured-*.json` through the same folder as the reports (`PREBUILT_ENV`). Pointing that at a persistent cache would make `test:scaling` assert yesterday's numbers. Measurements stay per run (Task 9 test `keeps measurements per run and reports across runs`).
2. **A cached report built by an older writer.** The cache folder is named by a hash of the generator's import closure; a file the generator imports but the key omits would serve stale reports (Task 9 test `the cache key covers every file the generator imports`; Task 11 compares a fresh build with the cached one).
3. **A pooled DuckDB returning another open's bytes under the same file name** (the prototype's service-share-parity failure). Task 15 test `a second open that registers other bytes under the same name reads the new bytes`.
4. **The pool's per-open prefix leaking into what tests see** (`filename` columns). `rows()` strips it (Task 15 test `filename reads back without the open's prefix through rows()`); a test that asserts a bare filename from Arrow results opts out with `{ pooled: false }`.
5. **Merged shard coverage that differs from the serial run.** Task 17 compares the merged totals with the last serial run's and falls back to a sharded coverage job if they differ by more than 0.1 point.
