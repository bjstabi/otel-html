# otel-html M5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship milestone M5 of otel-html: an OTLP receiver (HTTP and gRPC) over the writer session, the `serve` and `run` commands, the three SDK exporters, the receiver load workflow, and CI dogfooding.

**Architecture:** One receiver core (`src/receiver/receiver.ts`) wraps a `WriterSession` and turns a request body into one `add` per resource entry, so partial success and backpressure are decided once. Two thin transports (`node:http`, `@grpc/grpc-js`) parse their framing and map the core's outcomes through one status table. `startReceiver` is the Node-side composition root the `serve` and `run` commands use; `run` adds a child process and a root span. The exporters call `Report` directly and map SDK objects with new `sdk-logs` and `sdk-metrics` modules checked against `@opentelemetry/otlp-transformer`.

**Tech Stack:** unchanged from M4, plus two runtime dependencies: `@grpc/grpc-js` 1.14.6 (pinned) and `@opentelemetry/resources` 2.12.0 (moved from devDependencies). `@opentelemetry/core` 2.12.0 joins devDependencies. The four SDK packages (`sdk-trace-base`, `sdk-logs`, `sdk-metrics`, `core`) become optional peer dependencies (`>=2`) and are imported as types only.

**Spec:** `docs/superpowers/specs/2026-10-29-otel-html-m5-design.md`, on top of `docs/superpowers/specs/2026-10-25-otel-html-design.md` (§5, §6, §7.5, §7.6, §10, §11.2, §16). Conventions: the M1–M4 plans in `docs/superpowers/plans/`.

**Scope boundaries (M5 only):** no live following in the viewer, no TLS or auth, no log or point dedupe, no receiver env vars.

**Plan-level calls (flag at review if wrong):**
- **New Node-side dirs** `src/receiver/`, `src/exporters/`, `src/run/`. Not in Biome's `noNodejsModules` override. `src/run/root-span.ts` and `src/receiver/signals.ts`, `status.ts` are pure (no `node:*`), the rest may import Node.
- **Internal access to a report's session:** `src/api/report.ts` exports `sessionOf(report: Report): WriterSession` and `configOf(report: Report): ResolvedConfig`, backed by a module-private `WeakMap` filled in the constructor. Neither is exported from `src/api/index.ts`.
- **Error codes:** `ErrorCode` gains `'receiver-busy'`. Transport-only outcomes (415, 404, 405, 413) are raised inside the transports as `OtelHtmlError('unsupported-input' | 'usage')` and mapped by the table, never thrown to callers.
- **`CliIo` gains** `signals: { on(fn: (signal: 'SIGINT' | 'SIGTERM') => void): () => void }` and `spawn: typeof import('node:child_process').spawn`. `main.ts` wires `process.on` and Node's `spawn`; tests pass a fake `signals` and the real `spawn`.
- **Sources:** records received over HTTP get `source` `otlp/http#<n>`, over gRPC `otlp/grpc#<n>` (n = the receiver's request counter), so writer error messages name the request.
- **Response messages** are built with `create(<Response>Schema, …)`; `partialSuccess` is set only when `rejected > 0`. JSON responses use `toJson` (int64 counts come out as strings, which OTLP JSON permits).
- **Rejected counts** per entry: spans = `Σ scopeSpans[].spans.length`; logs = `Σ scopeLogs[].logRecords.length`; metrics = the number of data points over every metric's kind (gauge/sum/histogram/exponentialHistogram/summary `dataPoints.length`). For a JSON metrics entry with `plain`, count the same way from `request` (decoded lazily; only on rejection).

## Global Constraints

Everything in the M1–M4 plans' Global Constraints still applies. Restated where M5 touches it:

- No `any`, no non-null assertions, exhaustive `switch` via `never`, typed `OtelHtmlError`s with `path`/`expected`/`actual`/`hint`. Biome strict at error. `mise run check` < 60 s: receiver tests bind port 0 on `127.0.0.1` and close their servers in `finally`/`afterEach`.
- Fail fast at every boundary: body size, content type, encoding, JSON/protobuf decode, config (`receiver.*` through Zod), CLI flags (ports 0–65535, both transports disabled is a usage error).
- Dependency injection: `startReceiver` and the commands take their collaborators (`WriterDeps`, `CliIo.signals`, `CliIo.spawn`); no module-level state. One composition root per entry point (`main.ts`, `src/api/receiver.ts`).
- Domain rules are data tables: `SIGNAL_SERVICES` (path, gRPC service, schemas, rejected field, record counter), `OUTCOME_STATUS` (outcome → HTTP status, gRPC code, retryable), `CORS_ORIGIN`, `CHILD_ENV` (the variables `run` sets and their derivation), `EXIT_CODE_OF_SIGNAL`.
- Exporters import `@opentelemetry/sdk-*` and `@opentelemetry/core` as **types only** (a test asserts it).
- Never silently wrong: a rejected entry is counted and named; a dropped tail in `run` is documented; the binary says when gRPC is unavailable.
- Targets (ubuntu-latest): `serve` peak RSS < 512 MB on 1M spans + 10M logs; the resulting report's Traces and Logs landings interactive < 3 s × factor.
- Conventional commits. Each commit message ends with the session's `Co-Authored-By` and `Claude-Session` trailers.
- Git hooks may not be installed in the checkout: run `pnpm exec biome check .` and `mise run typecheck` by hand before each commit, never through a pipe that hides the exit status.

## Review Focus

1. **A protobuf body whose second resource entry has a 15-byte trace id.** Expected: the first entry is written, the response is 200 with `partialSuccess.rejectedSpans` equal to the bad entry's span count and `errorMessage` naming `resourceSpans[1]`. Pinned in Task 3 and Task 4.
2. **A gzip JSON body of `{}` with `Content-Type: application/json; charset=utf-8`.** Expected: 200, response body `{}`, nothing written, the content type echoed. Pinned in Task 4.
3. **A sender that retries after a 503.** Expected: retried spans are deduplicated by the writer and the second response counts them as accepted; the README says logs are not deduplicated. Pinned in Task 4.
4. **`run` whose child is killed by SIGTERM.** Expected: exit code 143, root span status `ERROR` "killed by SIGTERM", no `process.exit.code` attribute, the report complete. Pinned in Task 8.
5. **`serve` receiving a second SIGINT while finishing.** Expected: exit 130, the lock released, the report at its last checkpoint with `complete: false`. Pinned in Task 7.

### Task 3: Receiver core

**Files:**
- Create: `src/receiver/receiver.ts`
- Test: `test/receiver/receiver.test.ts`

**Interfaces:**
- Consumes: `WriterSession` (`add(entry, source, { partial: true })`, `endInput()`), `OtlpJsonStream`, `streamOtlpProtobuf`, `SIGNAL_SERVICES`, `Logger`, `Tracer`.
- Produces:
  ```ts
  export type BodyEncoding = 'json' | 'protobuf';
  export interface ReceiveResult { accepted: number; rejected: number; errorMessage: string | null }
  export interface ReceiverStats {
    requests: number;
    bytes: number;
    accepted: Record<OtlpSignal, number>;
    rejected: Record<OtlpSignal, number>;
  }
  export interface ReceiverOptions { inflightBudgetBytes: number }
  export interface Receiver {
    /** `transport` names the source: `otlp/http` or `otlp/grpc`. */
    receive(signal: OtlpSignal, body: Uint8Array, encoding: BodyEncoding, transport: string): Promise<ReceiveResult>;
    stats(): ReceiverStats;
    /** Stop accepting (later receives fail `receiver-busy`), wait for the receives in progress. Idempotent. */
    close(): Promise<void>;
  }
  export function createReceiver(session: WriterSession, options: ReceiverOptions, deps: { logger: Logger }): Receiver;
  ```
- Behaviour, as spec §5.1: receives run one at a time through an internal promise queue (the session's `partial` flag is session-wide, so a request's adds and `endInput()` must not interleave with another's); decode per entry; `protobuf` → `streamOtlpProtobuf(body, signal, source)`; `json` → `new OtlpJsonStream(source, { lines: false })`, `push(text)` then `end()`; a JSON document whose signal key is another signal's is `invalid-otlp` (`expected resourceSpans`), `{}` is a success with nothing (so `noSignal` from the stream is caught and turned into an empty result only when the body holds no signal key at all; a body with the wrong key still fails). Entries are added in order; an entry failing with `invalid-otlp` or `time-out-of-range` is counted rejected with the message kept (first wins); any other error is rethrown after `endInput()` is attempted. If entries > 0 and accepted entries = 0 → throw `OtelHtmlError('invalid-otlp', { message })`. In-flight budget as spec §5.1. `requests` increments per receive, `bytes` by `body.length`.

- [ ] **Step 1: Write failing tests** with `createTestWriter` + `openSession` (memory fs):
  - a JSON traces body with 2 entries of 2 spans → `{ accepted: 4, rejected: 0, errorMessage: null }` and the report has 4 spans.
  - a protobuf body (built with `create`/`toBinary` of `ExportTraceServiceRequestSchema`) with entries [good 2 spans, bad trace id 15 bytes, good 1 span] → `{ accepted: 3, rejected: 1, errorMessage }` with `errorMessage` matching `/resourceSpans\[1\]/`, and the report has 3 spans.
  - a body whose only entry is bad → rejects with `invalid-otlp`.
  - `{}` and `{"resourceLogs":[]}` on `logs` → accepted 0; `{"resourceLogs":[]}` on `traces` → `invalid-otlp`.
  - `[1,2]` and `not json` → `invalid-otlp`; an empty `Uint8Array` on protobuf → accepted 0.
  - Budget: `inflightBudgetBytes: 100`; a 60-byte receive in flight (block the session with a slow fake `add`) plus a second 60-byte receive → the second rejects `receiver-busy` immediately; a lone 150-byte receive with nothing in flight succeeds.
  - Serialization: two concurrent receives against a fake session that records the order of `add`/`endInput` calls → the second request's first `add` comes after the first request's `endInput`.
  - Epoch: a first request at T, then one at T − 1 h → both accepted (offsets are signed); one at T + 200 days → rejected with `time-out-of-range` counted in `rejected`.
  - `close()` resolves after the in-flight receive finishes; a receive after `close()` rejects `receiver-busy`.
  - `stats()` after the above: `requests`, `bytes`, `accepted.traces`, `rejected.traces`.
  - A fake session whose `add` throws `new Error('disk full')` → `receive` rejects with that error, and `stats().rejected` is unchanged.
