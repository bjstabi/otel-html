Dashboards come from config (Fusion ships with the library)

# otel-html.yaml (or passed to the API as an object)
dashboards:
  - id: checkout
    title: Checkout service
    variables: [service.name, host.name]          # dropdowns in the filter bar
    widgets:
      - { type: timeline, x: 0, y: 0, w: 12, h: 6 }
      - { type: traces, query: "service.name=payments status=error", x: 0, y: 6, w: 7, h: 13 }
      - { type: logs, query: "severity>=WARN", x: 7, y: 6, w: 5, h: 13 }
      - type: metric                                           # same query model as the Metrics Explorer
        queries: [{ metric: http.server.request.duration, show: p95, by: [http.route] }]
        x: 0, y: 19, w: 6, h: 7

Dashboards list. Fusion is built in and is the default. Other dashboards come from the config file, or from objects passed to the library API, and each row shows where it came from. Making a dashboard the default means opening the report lands on it.

Fusion layout. A 12-column grid. A full-width Timeline sits on top with one row each for spans (error part in red), logs (stacked by severity) and metric points, all on the same time axis. Below are the Traces, Logs and Metrics widgets. Drag ⠿ moves a widget, ◢ resizes it, and "Edit layout" → "Copy config" exports the layout.

Two kinds of filter. Variables (service.name, environment, host.name) are template variables that apply to every widget. Selection chips come from interacting with widgets: dragging on the timeline or a chart adds a time range, clicking a trace adds its trace_id, and clicking an exemplar adds its trace. Each chip has ✕, and there's a Clear all.

Following the selection. Each widget has a "⛓ follows selection" toggle, so a widget can be pinned to its own view. The Logs widget has Only matches / Show context: matching logs alone, or all logs in the time window with the matches highlighted. Metrics follows the resources of the selected trace and marks the selected time window.

Same components. The widgets are the shared Trace list, flame graph, Log list and Chart card, and the config uses the same query syntax as the explorers. Every widget's "Open in …" carries both its filters and the current selection.
