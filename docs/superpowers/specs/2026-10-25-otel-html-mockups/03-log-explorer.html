The span that emitted the log is outlined, and a dashed line marks the log's timestamp. Clicking a span opens the trace panel on that span. With no trace_id, the tab is hidden and the Trace card in the header reads "no trace".

Same frame as Traces. Same sidebar, query tokens, View switcher, facet column (with value bars and only/exclude), histogram card and results table, so learning one explorer teaches the other.

OTel-native columns and facets. Severity comes from SeverityNumber, shown with its SeverityText (ERROR · 17). Service, host.name and Scope come from the resource and instrumentation scope. event.name and a Has trace facet are added. Vendor concepts like log indexes and sources don't exist in OTel and are left out.

Group into: Logs · Patterns · Traces. Patterns groups similar bodies; the writer precomputes the clusters. Traces groups logs by trace_id. Patterns also gets its own entry in the sidebar.

Body. Rendered according to the OTel AnyValue type. A string shows raw or wrapped, with key=value and JSON highlighting. A map or array shows as a tree. "Lines" sets how many body lines each table row shows.

Detail panel. A header with severity, timestamp and observed timestamp, plus fact cards for service, host, scope and trace (trace and span IDs are links). Tabs: Attributes (shared attribute-groups component), Trace (when trace_id is present), Metrics (the shared chart, marked at this log's time), Surrounding logs (the shared log list: same service and host, ±N records), and Resource.

No Live Tail. The report is static. If the receiver is still writing the report, a "following" badge could appear and new data would load in. That's a decision for later.
