① Run card. Shows which report you're looking at, its time span, and totals for each signal. Each nav item has a keyboard shortcut (g t, g l, …).

② Spans / Traces. Search individual spans, or whole traces.

③ Views. Saved views. Some are defined in the writer's config (they ship inside the report), and viewers can save their own locally. Mirrored by the "Saved views" tab in the facets column.

④ Time. Defaults to the entire run. ◀ ▶ step through the run, ⤢ zooms out, and dragging on any chart narrows the range. There's no live or pause control, because the report is static.

⑤ Query bar. Each filter is a key / operator / value token (=, ≠, ~ wildcard, >, <), and free text searches every attribute. + Query adds a second span query. Copy link puts the whole state in the URL, so a link reopens the exact view even from a local file.

⑥ Group by + View. List, Timeseries, Top list, Bar, Table, Point plot, Treemap, Pie. No service flow map (it needs service-map data OTel doesn't provide).

⑦ Summary strip. Requests, Errors and Latency (p50/p75/p90/p95/p99/max), with "Analyze" shortcuts for errors and slow spans. It collapses with "Hide summary".

⑧ Facets. The list shows 30 of 40 facets; + Add brings in any attribute key present in the data. Each value has a share-of-total bar behind it and hover actions only · exclude. Duration is a histogram with a draggable range, not separate min/max boxes. Long value lists have a "Filter values" box.

⑨ Columns + Export. Choose any attribute as a column (e.g. error.message). Export the current results as CSV, JSON, or OTLP JSON.

⑩ Latency by service. Each trace's time split across its services, using the same service colors as the facets. Status is a labeled dot, never just a colored bar, and HTTP codes are outlined pills tinted by class (2xx, 3xx/4xx, 5xx).
