# Working in otel-html

`otel-html` turns OpenTelemetry traces, logs and metrics into a static HTML report (writer and CLI under `src/`, the
viewer under `src/viewer/`). The README is the product documentation; this file is for whoever writes code here,
human or agent. Read only what the links below say applies to you.

## The development loop

Run the smallest check that can catch the mistake, and run it often. CI runs the same mise tasks.

| when | run | cost |
|---|---|---|
| after every edit | `mise run check` (lint, typecheck, unit tests, knip) | ≈ 20 s |
| while iterating on one module | `pnpm exec vitest run <test file>` or `pnpm exec vitest run --changed main` | seconds |
| after a viewer or report-path change | `mise run test:e2e:chromium -- e2e/<spec>.spec.ts` | the spec plus the fixture setup |
| before every push | `mise run check` (the pre-push hook runs it too) | ≈ 20 s |
| before opening a PR | `mise run check` then `mise run test:e2e:chromium` (`mise run verify` once it exists) | ≈ 2 min |
| never locally | the three-browser matrix, the windows unit run, metrics-scale, the binaries | CI's job |

The e2e suite before a PR is a rule, not a hook, so a failure that reaches CI is a measurable event. `mise run
build` first if `dist/` is missing. The tasks document themselves: `mise tasks ls` for the list, `mise tasks info
<task>` for the full description (the slow ones, `test:load*` and `bench:metrics`, say what they cost).

## Conventions

[docs/agents/conventions.md](docs/agents/conventions.md): branches, commits and PR titles (squash-merge; the title
is the conventional commit), TDD, what to run before a commit, how to report what you found on the way. Read it
before your first commit.

## Which PR process

Before starting work that will produce a pull request, ask the maintainer which process applies, then read only
that file:

- [Unattended](docs/agents/process-unattended.md): PRs are reviewed on the branch and squash-merged when CI is
  green, without waiting for the maintainer.
- [Reviewed](docs/agents/process-reviewed.md): PRs wait for the maintainer's review; the maintainer merges.
- [Spike](docs/agents/process-spike.md): a throwaway branch to learn something; no PR.

## Where things are

- `mise.toml`: every task CI and developers run. `.github/workflows/ci.yml`: the jobs, which call those tasks.
- `docs/superpowers/specs/`: design documents. `docs/superpowers/plans/`: implementation plans, one per project.
- `e2e/`: Playwright specs; `e2e/global-setup.ts` builds the fixture reports it serves. `test/`: vitest, mirrors `src/`.
- `fixtures/`: OTLP inputs regenerated by `mise run fixtures`; `src/model/gen/` is generated by `mise run gen`.
